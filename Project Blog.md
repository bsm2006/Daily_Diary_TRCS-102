## 5. Natural Language Processing for Movie Recommendations

One of the most important components of the project was the application of Natural Language Processing (NLP).

Movie descriptions and other textual attributes contain information that can help identify movies with similar themes and content.

However, machine learning algorithms cannot directly perform mathematical similarity calculations on raw text.

Therefore, textual information must first be converted into numerical representations.

The project implemented three approaches:

1. CountVectorizer.
2. TF-IDF.
3. Sentence-BERT.

### 5.1 CountVectorizer

CountVectorizer converts text into numerical representations based on word occurrence.

It creates a document-term matrix in which:

- Each row represents a document or movie.
- Each column represents a word from the vocabulary.
- Each value represents the frequency of that word in the corresponding document.

Movies with similar word distributions can be identified by comparing their vector representations.

The project stores the fitted CountVectorizer and its generated sparse matrix.

Files used:

```text
models/count_vectorizer.pkl
models/count_vectors.npz
```

### 5.2 TF-IDF

TF-IDF stands for Term Frequency-Inverse Document Frequency.

Unlike simple word-count representation, TF-IDF assigns importance to words based on their frequency within a document and their distribution across the complete collection of documents.

The general TF-IDF representation is:

\[
TFIDF(t,d)=TF(t,d)\times IDF(t)
\]

Where:

- \(TF(t,d)\) represents the frequency of term \(t\) in document \(d\).
- \(IDF(t)\) represents the inverse document frequency of that term.

This approach gives relatively greater importance to informative words and reduces the influence of terms that occur frequently across many documents.

The project stores the fitted TF-IDF vectorizer and its generated sparse matrix.

Files used:

```text
models/tfidf_vectorizer.pkl
models/tfidf_vectors.npz
```

### 5.3 Sentence-BERT

Sentence-BERT is a transformer-based approach used to generate dense semantic embeddings for textual information.

Unlike basic word-count methods, it can represent contextual and semantic relationships between words and sentences.

The project uses 384-dimensional BERT embeddings to represent movie information.

These embeddings allow the system to identify movies with related meanings and themes, even when their descriptions do not contain exactly the same words.

Stored resource:

```text
models/bert_embeddings.npy
```

### 5.4 Comparison of Text Representation Techniques

| Parameter | CountVectorizer | TF-IDF | Sentence-BERT |
|---|---|---|---|
| Representation | Word frequency | Weighted word frequency | Dense semantic embeddings |
| Context Understanding | Limited | Limited | Contextual |
| Semantic Similarity | Basic | Improved weighting | Stronger semantic representation |
| Representation Type | Sparse | Sparse | Dense |
| Main Advantage | Simple and lightweight | Highlights informative terms | Captures semantic relationships |

The project integrates all three methods so that their recommendation outputs can be explored and compared.

## 6. Cosine Similarity and Recommendation Generation

After converting movie information into numerical representations, the next step was to identify similar movies.

Cosine Similarity was used to calculate the similarity between two movie vectors.

The mathematical representation is:

\[
\operatorname{CosineSimilarity}(A,B)=
\frac{A\cdot B}{\|A\|\|B\|}
\]

Where:

- \(A\) and \(B\) represent two movie vectors.
- \(A\cdot B\) represents their dot product.
- \(\|A\|\) and \(\|B\|\) represent their vector magnitudes.

The similarity value indicates how closely two vectors are aligned.

### 6.1 Recommendation Workflow

The recommendation process follows these steps:

1. The user selects a movie.
2. The system identifies the selected movie's index.
3. The corresponding numerical representation is retrieved.
4. Cosine Similarity is calculated against the available movie representations.
5. Similarity scores are sorted in descending order.
6. The selected movie itself is excluded from the results.
7. The top 10 similar movies are returned.

The project implements three separate recommendation functions:

```python
recommend_count(movie_key, top_n=10)

recommend_tfidf(movie_key, top_n=10)

recommend_bert(movie_key, top_n=10)
```

Each function uses its respective representation and similarity calculation.

The returned recommendations contain:

- Movie key.
- Movie title.
- Release year.
- Primary genre.
- Similarity score.

### 6.2 Recommendation Resource Management

To avoid rebuilding all numerical representations whenever the application runs, the project stores precomputed resources.

The following resources are loaded by `recommender.py`:

```text
models/
│
├── movie_data.pkl

├── tfidf_vectorizer.pkl
├── count_vectors.npz

```

The application loads these resources and uses them directly during recommendation generation.

This separates the recommendation engine from the user interface and keeps the application modular.

### 11.3 Resolving Case-Sensitive File Path Issues

One deployment issue involved the stylesheet path.

The application initially referenced:

```text
Assets/style.css
```

However, the actual directory was:

```text
assets/style.css
```

The cloud environment treated these paths as different because of case sensitivity.

The reference was corrected to match the actual directory name.

### 11.4 Resolving Matplotlib Rendering Issues

The application also experienced Matplotlib chart-rendering issues in the cloud environment.

The affected visualizations were present in the Analytics and Dataset pages.

To address this, a supporting module named `image_renderer.py` was introduced.

The function:

```python
render_matplotlib_base64(fig)
```

converted Matplotlib figures into Base64-encoded image representations.

This alternative rendering approach was applied to the affected charts instead of relying directly on `st.pyplot(fig)`.

The changes were committed and pushed to GitHub, after which the deployed application was checked again.
